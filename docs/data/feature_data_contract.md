# Feature Data Contract — Banking Fraud Intelligence Copilot

## 1. Purpose

This document defines the input data contract for the initial fraud detection model using the PaySim synthetic transaction dataset.

**Prediction scenario:** Pre-transaction fraud risk assessment.

The model should use information available before a transaction is executed. Post-transaction information must not be used as a prediction input.

## 2. Source dataset

| Property | Description |
|---|---|
| Dataset | PaySim |
| Source file | `data/raw/paysim.csv` |
| Total records | 6,362,620 |
| Total columns | 11 |
| Target column | `isFraud` |
| Fraud records | 8,213 |

PaySim is a synthetic mobile-money transaction dataset. It does not represent actual banking transactions.

## 3. Source-to-feature data contract

| Source column | Business meaning | Availability | Decision |
|---|---|---|---|
| `type` | Transaction type | Before execution | Include |
| `amount` | Proposed transaction amount | Before execution | Include |
| `oldbalanceOrg` | Sender's previous balance | Before execution | Include |
| `oldbalanceDest` | Recipient's previous balance | To be verified | Conditional |
| `newbalanceOrig` | Sender's updated balance | After execution | Exclude |
| `newbalanceDest` | Recipient's updated balance | After execution | Exclude |
| `nameOrig` | Sender identifier | Before execution | Exclude initially |
| `nameDest` | Recipient identifier | Before execution | Exclude initially |
| `isFraud` | Fraud label | Training label | Target only |
| `isFlaggedFraud` | Simulator-generated fraud flag | Not approved as an independent input | Exclude |
| `step` | Simulation time step | Available in dataset; predictive use pending validation | Pending |

## 4. Initial model input features

The initial candidate feature set is:

- `type`
- `amount`
- `oldbalanceOrg`

`oldbalanceDest` will be considered separately after confirming that recipient balance information is available before transaction execution.

## 5. Excluded features

### Post-transaction fields

- `newbalanceOrig`
- `newbalanceDest`

These fields contain updated balances after the transaction. Their use would introduce target leakage into a pre-transaction prediction model.

### Simulator-generated flag

`isFlaggedFraud` is excluded because it is generated by the simulator's own rule-based logic. It should not be used as an independent predictive input.

### Identifiers

`nameOrig` and `nameDest` are excluded from the initial model. Their potential value can be investigated later through separate entity-level analysis.

## 6. Target definition

| Column | Role |
|---|---|
| `isFraud` | Binary classification target |

- `0` — Non-fraudulent transaction
- `1` — Fraudulent transaction

The target must never be included in the model input features.

| `step` | Pending | Assess temporal modelling and validation requirements |

## 8. Data leakage prevention rules

1. Use only features available at the prediction point.
2. Never use post-transaction balances as pre-transaction inputs.
3. Keep `isFraud` separate from model features.
4. Exclude simulator-generated flags from predictive inputs.
5. Fit preprocessing and feature transformations using training data only.
6. Validate feature availability before approving new derived features.

## 9. Project limitations

PaySim is a synthetic dataset. The dataset alone cannot establish which fields a real banking system would expose before transaction execution.

Feature availability assumptions must be documented and treated as modelling assumptions until verified against a real transaction-processing design.
